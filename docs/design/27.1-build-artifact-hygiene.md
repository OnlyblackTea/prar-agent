# 27.1 构建产物卫生修复（.gitignore 锚定 + tsconfig noEmit）

> 前置：M4-27 收口时发现两处"构建/运行产物污染仓库与测试"的缺陷。
> 本设计为独立修复任务，不属 ROADMAP 任何 milestone，编号沿用 15.1 的小数先例。
> 用户决策：与 24.1（consolidator 测试隔离）、27.2（App.tsx effect 依赖）分别独立成 commit。

## 1. 背景与目标

M4-27 实施期间踩到两个独立的产物泄漏缺陷，均已实测复现：

**缺陷 A —— `.gitignore` 模式锚定错位。**
`.gitignore:43` 为 `sandbox/runs/`。gitignore 规则：**含斜杠的模式锚定到该 `.gitignore` 所在目录**（此处为仓库根），因此它只匹配 `<root>/sandbox/runs/`，匹配不到 `backend/sandbox/runs/`。

实测证据：

```
$ git check-ignore -v backend/sandbox/runs
（无输出 —— 未被忽略）
$ git status --porcelain
?? backend/sandbox/
```

而实际产生该目录的代码是 `backend/src/app/core/action_dispatcher.py:37`：

```python
_DEFAULT_SANDBOX_BASE = Path("sandbox/runs")
```

这是**相对路径**，落地位置取决于进程 CWD。uvicorn 从 `backend/` 启动，故实际写入
`backend/sandbox/runs/<session_id>/`。仓库根**从来没有** `sandbox/` 目录
（`ls -d sandbox` → 不存在）。结论：`.gitignore:43` 自写下之日起就是错的 ——
它按"仓库根即 CWD"的假设书写，与真实运行拓扑不符。

后果：每个跑过 action 的会话都在 `git status` 里留一条 `?? backend/sandbox/`，
既污染状态输出，也存在被 `git add .` 误纳入的风险（该目录内是 embedded git
repository，见既有记忆 `embedded-repo-gitignore`）。

**缺陷 B —— `frontend/tsconfig.json` 未禁用 emit。**
`frontend/package.json` 的 `build` 脚本是 `tsc -b && vite build`。`tsconfig.json`
既无 `noEmit` 也无 `outDir`，且 `include: ["src"]`，因此 `tsc -b` 会把编译产物
`.js` **就地吐进 `src/`**，与同名 `.ts`/`.tsx` 源文件并排。

实测证据：

```
$ npx tsc -p tsconfig.json --showConfig | grep -i "noemit\|outDir"
（无输出 —— emit 开启且无 outDir）
$ npx tsc -b --dry
03:02:45 - Project '.../tsconfig.node.json' is up to date
03:02:45 - A non-dry build would build project '.../tsconfig.json'
```

后果已在 2026-09-04 实际发生：`src/` 下累积 36 个陈旧 `.js`（184K），
Vite/vitest 的模块解析中 `.js` **遮蔽**同名 `.ts`/`.tsx`，导致"改了源码但测试
行为不变"的假失败，vitest 从 `10 files / 117 passed` 退化为 `12 failed | 41 passed`。
且因 `frontend/.gitignore:13` 是 `src/**/*.js`，这些产物对 `git status` /
`git ls-files` **完全不可见**，排查时极易误判为代码回归（见既有记忆
`frontend-stale-js-shadowing`）。

注：`tsconfig.node.json` 是 `composite: true` 且无 `noEmit`，会产出
`vite.config.js` / `vite.config.d.ts` —— 这两个已被 `frontend/.gitignore:15-16`
显式忽略，属预期行为，本次**不动**。

**目标**：两处产物泄漏各自在源头堵住，且**零运行时行为变化**、**零新依赖**。

## 3. 接口设计

无 API / schema / 函数签名变更。两处均为配置文件修改。

**A —— `.gitignore:43`**

```diff
- sandbox/runs/
+ **/sandbox/runs/
```

选 `**/` 前缀而非硬编码 `backend/sandbox/runs/`：`_DEFAULT_SANDBOX_BASE` 是相对
路径，落地目录随进程 CWD 变化（从仓库根启动 uvicorn 就会落到 `<root>/sandbox/runs/`）。
`**/sandbox/runs/` 对两种 CWD 都成立，不依赖对启动方式做假设。

**B —— `frontend/tsconfig.json` `compilerOptions`**

```diff
    "isolatedModules": true,
+   "noEmit": true,
    "baseUrl": ".",
```

选 `noEmit` 而非 `outDir`：该项目的类型检查职责由 `typecheck` 脚本
（`tsc --noEmit`）承担，产物打包职责由 `vite build` 承担，`tsc -b` 在此仅用于
build 模式下顺带做项目引用（`tsconfig.node.json`）的类型校验 —— 它**不应该**
产出任何 `src/` 下的文件。`outDir` 只是把垃圾挪个位置，`noEmit` 才是根因修复。

## 7. 风险与未决

| 风险 | 评估 | 处置 |
|---|---|---|
| `tsc -b`（build 模式）拒绝 `noEmit` 项目 | 中。TS 的 TS6304「Composite projects may not disable emit」只约束 `composite: true` 的项目；根 `tsconfig.json` 非 composite，理论上不受限。 | 以 V4/V5 实测为准；若 `tsc -b` 报错，改为标准 Vite 布局（根 `tsconfig.json` 置 `files: []` + references 到新增 `tsconfig.app.json` 承载 `src` 与 `noEmit`），并在本文追加「## 设计变更」章节。 |
| `**/sandbox/runs/` 误伤将来某处同名源码目录 | 低。仓库内 `sandbox/runs` 语义唯一（运行期产物）。 | 不处置；如将来出现，改用更精确的 `backend/sandbox/runs/` + `<root>/sandbox/runs/` 两行。 |
| 已存在的 `backend/sandbox/runs/4a0ab865-…/` 是否要删 | —— | **不删**。它是 27 号实施记录逐字引用的 git 证据（`b94b9b6` / `fc74639` Revert / `7a11ef1` / `90fed64`）。本次修复后它只是从「未跟踪」变为「被忽略」，文件保持原样。 |
| 缺陷 B 的产物是否会再次出现 | 已消除源头 | 修复后任何 `tsc -b` / `npm run build` 都不再向 `src/` 写文件。既有记忆 `frontend-stale-js-shadowing` 的「根因」段需在收口时更新为「已修复」。 |
