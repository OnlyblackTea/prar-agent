## 1. 目标

把 `make typecheck`（= `uv run mypy src tests`，`Makefile:19`）从**实测 20 错**降到 **0 错**，
且**不改一行 `src/` 生产代码**。

## 4. 修复原则

1. **只动 `tests/`。** 生产类型签名一行不改 —— 为了消一个测试报错去改生产 API，属于禁止事项里的"无关重构"。
2. **`cast` 优先于 `# type: ignore`。** `cast` 精确到"这一个表达式当这一个类型用"；
   `# type: ignore[arg-type]` 会连带屏蔽**同一行上未来新出现的**真 arg-type 错误。
   这也是 `15.1` 的既有裁决（"测试代码：优先简洁性（cast），减少噪声"）。
3. **`cast` 优先于 `assert isinstance`。** 替身本来就不是生产类的实例，`isinstance` 必然失败；
   这里要的是类型层面的断言，不是运行时的。
4. **cast 的落点由"谁读 `.calls`"决定。** 若测试后续还要访问替身自有属性，
   cast 必须**内联在关键字实参上**，绝不能盖在局部变量上（否则局部变量被窄化成生产类型，自有属性访问全部报错）。
5. **不留 dead ignore。** `strict = true` 含 `warn_unused_ignores`：
   任何让既有 `# type: ignore` 变冗余的修复，都会把它**转化成一个新的错误**。同一改动里必须一并删掉。

## 5. 分类修复方案

### 5.1 C1 — `_FakeEmbedding`（8 处）：内联 `cast(EmbeddingService, …)`

**`test_recall_service.py`**（1 处，`:42`）
唯一咽喉点是 `_svc`，且该文件的 `_FakeEmbedding` **没有 `calls` 属性、也没有任何断言读它**，
所以直接在构造处 cast 最省：

```python
from typing import cast                      # 新增
from app.core.embedding import EmbeddingService   # 新增

def _svc(db: AsyncSession) -> MemoryService:
    return MemoryService(db, cast(EmbeddingService, _FakeEmbedding()))
```

**`test_consolidator_service.py`**（7 处：`:147, :161, :163, :312, :314, :334, :336`）
三个 helper 的形参注解**保持 `_FakeEmbedding` 不变**（改成 `EmbeddingService` 会迫使 6+ 个调用点跟着改，
diff 更大且无收益），只在**注入进生产类的那一刻** cast：

```python
from typing import Any, NamedTuple, cast      # 改：加 cast
from app.core.embedding import EmbeddingService   # 新增

async def _seed_memory(db: AsyncSession, emb: _FakeEmbedding, *, ...) -> models.Memory:

async def _run(db: AsyncSession, router: _FakeRouter, emb: _FakeEmbedding) -> Any:
    c = Consolidator(
        db=db,
        store=MemoryService(db, cast(EmbeddingService, emb)),   # :161
        router=router,  # type: ignore[arg-type]                # :162 保持不动
        embedding=cast(EmbeddingService, emb),                  # :163
    )

async def _pending_episodic_ids(db: AsyncSession, emb: _FakeEmbedding) -> set[UUID]:
    store = MemoryService(db, cast(EmbeddingService, emb))      # :178
    ...
```

两个测试体内联的 `Consolidator(...)` 同形处理：
`test_no_default_adapter_raises`（`:312` store / `:314` embedding）、
`test_llm_error_keeps_batch_unconsumed`（`:334` store / `:336` embedding）。

> **⚠ 必须同批删掉 `:178` 的 `# type: ignore[arg-type]` 及其上方 `:177` 的解释注释。**
> 那行 ignore 是 `24.1` 为了"净增 0"临时加的，cast 一上它就变冗余，

> `:162 / :313 / :335` 的 `router=` ignore **保持原样**（`_FakeRouter` 不在本次范围，它们仍然是活的）。

### 5.2 C2 — `_FakeLongTerm`（7 处）：内联 `cast(LongTermMemory, fake)`

**cast 只能落在 `long_term=` 关键字上，不能落在局部变量上** —— 该文件有 6 处读 `fake.calls`
（`:102, :103, :127, :142, :155, :165`），一旦 `fake = cast(LongTermMemory, _FakeLongTerm())`，
`fake` 的类型就变成 `LongTermMemory`，`.calls` / `.error` 全部报错。

```python
from typing import Any, cast                    # 改：加 cast
from app.memory.long_term import LongTermMemory  # 新增

await SessionService(db).complete(session_id=..., long_term=cast(LongTermMemory, fake))
```

7 个落点：`:99, :125, :140, :153, :163, :187`（都是 `long_term=fake`）
+ `:174`（`long_term=_FakeLongTerm()` 内联构造，同形 cast）。

`fake.error = EmbeddingTransportError(...)`（`:184`）不受影响 —— 它在 cast 之外作用于原始局部变量。

### 5.3 C3 — `Literal` 收窄（2 处）：改 helper 形参注解

**只改 `kind` 一个形参的注解**，两个 helper 的其余形参（`content` 在 `:60` 无默认值、在 `:79` 默认 `"k"`；
`importance` 两处均默认 `0.5`）与返回类型 `Any` **原样不动**：

```python
- def make_item(kind: str, ...) -> Any:
+ def make_item(kind: Literal["semantic", "procedural"], ...) -> Any:
```

两个文件各加 `Literal` 到既有 `from typing import Any` 行。返回类型保持 `Any` 不变
（改返回类型会波及各调用点的下游断言，超出范围）。
所有调用点已核对为字面量/默认值（§3.3），无需改动。

### 5.4 C4 — `union-attr`（2 处）：等价改写为 `assert_awaited_once_with`

`assert_awaited_once()` + 手写 `.await_args.kwargs` 比对，语义上**就等于** `assert_awaited_once_with(...)`，
后者内部已处理 `None`，且失败信息更好。这不是"为了过 mypy 而削弱断言"，是换成 mock 的正规写法：

```python
# test_action_dispatcher.py:673-674
- rollback.assert_awaited_once()
- assert rollback.await_args.kwargs == {"plan_version": 3, "step_id": "step_002"}
+ rollback.assert_awaited_once_with(plan_version=3, step_id="step_002")

# test_ws_plan.py:229-230
- mock_recall.assert_awaited_once()
- assert mock_recall.await_args.kwargs["query"] == "build a web app"
+ mock_recall.assert_awaited_once_with(query="build a web app")
```

> `test_ws_plan.py:232` 的 `mock_engine.generate.await_args.kwargs[...]` **不是错误**（那个 mock 是 `Any`），不动。
> 严格性等价性核对：原写法断言 `kwargs` **完全等于** `{"plan_version": 3, "step_id": "step_002"}`，
> `assert_awaited_once_with` 也是全等比对（同时额外要求 `args == ()`，而原调用点确实全是关键字调用），
> 故 C4 两处均为**不减弱**的等价替换。

## 6. 决策项

### D1（核心）：C1/C2 用 `cast`，**不**抽 Protocol —— 已裁决：cast

抽 Protocol 是"看起来更正确"的方案：在 `src/` 定义
`EmbeddingProtocol`（只含 `embed_one`）与 `LongTermProtocol`（只含 `record_episodic`），
让 `MemoryService` / `Consolidator` / `SessionService.complete` 按 Protocol 收参，替身自然满足，15 个错误一次归零。

**技术上可行**，爆炸半径已量过（全部源码兼容，调用点零改动）：

| 生产签名 | 若改 Protocol 需核对的构造/调用点 |
|---|---|
| `MemoryService(__init__)` | `api/memories.py:83`、`api/memories.py:98`、`api/sessions.py:110`、`api/ws_plan.py:54`、`main.py:38` —— 5 处 |
| `Consolidator(__init__)` | `api/memories.py:96`、`main.py:36` —— 2 处 |
| `SessionService.complete(long_term=…)` | `api/sessions.py:279`（由 `api/sessions.py:110` 的 DI 喂入）—— 1 处 |

**但仍然否决**，四条理由，按权重排：

1. **C2 根本没有忠实的 Protocol 可写。**
   `_FakeLongTerm.record_episodic` 返回 `None`，生产的返回 `Memory`。
   要让替身满足 Protocol，只能二选一：
   (a) 把生产的返回类型弱化成 `object` / `Any` —— 为了测试去**降低生产类型精度**，方向反了；
   (b) 把替身改写成构造并返回一个 ORM `Memory` 实例 —— 替身不再简单，且 `Memory` 需要 DB 身份，测试成本上升。
   两条都比 `cast` 差。C1 虽然签名完全对齐、Protocol 可写，但为了对称性也不该单独给 C1 开 Protocol。
2. **违反"禁止无关重构"。** 本任务的输入是"20 个 tests/ 类型错误"，产出却是 8 处生产签名变更 ——
   范围外溢，且会让这次 commit 的 diff 无法用"修测试类型"一句话解释。
3. **与项目既有 Protocol 的诞生方式不一致。**
   `src/` 里现有的 Protocol（`ActorProtocol` / `ActEventSink` @ `core/action_dispatcher.py:76,82`；
   `ShellRunner` / `StdoutEmitter` / `EventEmitter` @ `tools/base.py:35,55,61`）
   全部是在**各自功能的设计期**（M3-18 / M3-15-16）作为真实抽象需求提出来的，
   没有一个是事后为了消测试报错而回填的。回填会稀释这个约定。
4. **`test_consolidator_service.py` 已经选了"逐点抑制"这条路。**
   该文件现有 4 处 `# type: ignore[arg-type]`（`:162, :178, :313, :335`），
   其中 `:178` 与 `:147/:161/:312/:334` 是**完全同类**的错误却漏加了 ——
   说明当初是逐点打补丁、没打完。用 `cast` 把这条路走完，是**最小 diff 且风格自洽**的收口；
   换 Protocol 等于推翻该文件已生效的既有决定。

**边界（何时应重新评估）**：若将来 `src/` 出现**第二个**真实的 embedding/long_term 实现
（例如本地模型 embedding、或 NoOp long_term），Protocol 就从"为测试回填"变成"真实抽象需求"，
届时应按 D1 的量过的爆炸半径单开设计推进。

### D2：C1 不用 `MagicMock(spec=EmbeddingService)` —— 已裁决：cast

`test_consolidator.py:32-34` 已有先例（`MagicMock(spec=EmbeddingService)`）。
但两个服务级测试文件的 `_FakeEmbedding` 是**确定性伪嵌入**
（sha256 派生 → 同文本同向量、不同文本在 1536 维下近似正交），
merge 阈值 / decay / recall 排序的断言**依赖这个性质**。
换成 MagicMock 就得再包一层 `side_effect`，机械更多、可读性更差，而 `cast` 一行解决。
（`test_consolidator.py` 是单元级、用 MagicMock，本次不动它。）

### D3：C4 用 `assert_awaited_once_with` 而非 `cast`/`assert … is not None` —— 已裁决：前者

三种都能过 mypy。选 `assert_awaited_once_with` 是因为它是 `unittest.mock` 的正规 API、
断言强度不降反升（额外校验位置参数为空）、失败信息更可读，且**净删一行代码**。
加 `assert await_args is not None` 属于往测试里塞防御性代码；`cast` 在这里是掩盖问题而非表达意图。

### D4：C3 收窄形参而非在调用点 cast —— 已裁决：收窄形参

helper 的 `kind: str` 本身就比模型契约宽，这是**注解写错了**，不是"替身与生产不匹配"。
改对注解是一行、且让 helper 从此拒绝非法 kind，属于修根因。

## 11. 设计变更 (2026-09-04)

实施中触发了 §8 步骤 8 的停手条款：两处与本文档预期不符，均已在同一批内修正后才继续。

### 11.1 D3 的等价性论证对 `test_ws_plan.py:230` 不成立（已修正）

§5.4 / D3 断言「`assert_awaited_once()` + 读 `await_args.kwargs`」与「`assert_awaited_once_with(...)`」
严格等价。**这个论证漏掉了位置参数**，两处结论并不相同：

- `test_action_dispatcher.py:674` 成立 —— `patch("…GitCheckpoint.rollback_to", rollback)` 替换的是类属性，
  `AsyncMock` 不是描述符，实例访问不绑定 `self`；生产侧 `rollback_to(plan_version=…, step_id=…)` 全是关键字，
  故 `assert_awaited_once_with(plan_version=3, step_id="step_002")` 精确匹配，实测通过。
- `test_ws_plan.py:230` **不成立** —— `app/api/ws_plan.py:53` 的签名是
  `async def _recall_ltm(db: AsyncSession, *, query: str)`，`:97` 的调用是
  `await _recall_ltm(db, query=msg.init_request)`，**带一个位置参数 `db`**。按 §5.4 原样改写后实测失败：

  ```text
  AssertionError: expected await not found.
    Expected: _recall_ltm(query='build a web app')
      Actual: _recall_ltm(<AsyncSession object at 0x…>, query='build a web app')
  ```

  测试拿不到 endpoint 内部创建的 session 对象，无法把 `db` 写进期望值。
  **修正**：位置参数用 `unittest.mock.ANY` 占位 ——
  `mock_recall.assert_awaited_once_with(ANY, query="build a web app")`，并在 `:4` 的
  `from unittest.mock import …` 里加 `ANY`。这仍满足 D3 的初衷（单行严格断言、mypy 无 `union-attr`），
  且比原写法多锁住一条信息：位置参数恰好 1 个。

> **教训**：把 `await_args.kwargs` 断言改写成 `assert_awaited_once_with` 之前，必须先读被测函数的**完整签名**
> 确认没有位置参数。只盯着 `.kwargs` 会把「有一个位置参数 + 若干关键字参数」的调用误判为「全关键字调用」，
> 而 mypy 的 `union-attr` 报错完全不会提示这一点 —— 类型检查过了，运行时才炸。

### 11.2 内联 `cast(...)` 顶出 4 处 ruff E501（已修正；§10.1 风险表原先没有这一条）

`pyproject.toml` 的 `[tool.ruff] line-length = 100`。§5.2 / §5.3 给的改写都是「在原行内插入 `cast(X, y)`」，
实测把 4 行顶过 100 字符：

| `test_session_complete_service.py:154,164,188` | 102 | `SessionService(db).complete(...)` 调用拆三行（对齐同文件 `:174-176` 的既有风格） |

均为纯换行，无行为变化，`make lint` 已复绿。注意 `test_session_complete_service.py` 里 4 空格缩进的同类调用
（98 字符）不受影响，只有 8 空格缩进（`with pytest.raises(...)` 块内）的 3 处越界。
